# Please Don't Overdesign

No fluff. Keep visual overhead low.

- Start with the content and actions the user asked for. Every added element needs a concrete purpose.
- Omit copy that explains the obvious. Keep explanations that resolve ambiguity or help someone complete a task.
- Avoid repeating information across headings, badges, counters, and status lines.
- Use spacing, alignment, and typography for hierarchy. Add borders, cards, shadows, and icons only when they improve usability.
- Reserve stronger color, weight, and backgrounds for meaningful priority or state. Avoid stacking treatments when fewer communicate equally clearly.
- Work within the project's visual language. Preserve distinctive type, color, imagery, and density when they serve the experience.
- Do not fill empty space just because it is available.
- For appearance-only review, use a static mockup at the requested fidelity. Add interaction when requested or needed to evaluate behavior.
- Preserve necessary controls, labels, feedback, legibility, and accessibility, including keyboard focus and ways to distinguish states beyond color alone.

Before handing over, remove anything whose absence would not make the result harder to understand or use.

## Example: a contents panel

A contents panel may need only section names, entries, and page numbers. When context already supplies orientation, omit redundant titles, ranges, dividers, and progress footers. Use type and spacing for grouping, quiet metadata, and selective emphasis for the current entry. Keep controls and context that help people navigate.
