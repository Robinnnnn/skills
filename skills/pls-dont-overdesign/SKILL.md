# Please Don't Overdesign

No fluff. No explainer text by default. Keep it minimal; keep it light.

- Start with the content and actions the user asked for. Every added element needs a concrete purpose.
- Omit taglines, eyebrow text, introductory copy, instructional subtitles, and footers that explain the obvious.
- Do not repeat information across headings, badges, counters, and status lines. Show it once, where it helps.
- Use spacing and restrained typography for hierarchy. Add rules, borders, cards, shadows, icons, and color only when they make the content easier to use.
- Do not fill empty space just because it is available.
- For appearance-only visual review, make a flat, static mockup at the requested fidelity. Add interaction when requested or needed to evaluate behavior.
- Preserve necessary labels, accessible names, legibility, and error information.

Before handing over, remove anything whose absence would not make the result harder to understand or use.

## Example: a contents panel

An overdesigned contents panel might add “a way into the collection” above a large “contents” heading, divider rules, page ranges beside chapter names, a “you are here” footer, and a repeated page counter. A decorative scene and extra controls can also make a simple visual review unnecessarily involved.

A simpler version shows chapter names and entries on a flat page, with quiet page numbers beside individual entries. It omits the redundant title block, rules, footer, and chapter-level numbers. The hierarchy comes from type and spacing.
